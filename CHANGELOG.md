### Package (M2)

- **Native CRAP and the ratchet** (`internal/complexity`, `internal/crap`, `internal/gobuild`, `internal/exempt`, `internal/baseline`, `internal/ratchet`, `cmd/gotops/baseline.go`). Compiled from the step READYs; protocol 0.4.3 (rulings C2 and C3 of M2) is under Changed. The package is still unreleased (0.0.0).
  - Complexity (G0): the §6.3 count (`default` is not counted; closures count inside their function; a package-level literal is scored on its own), checked against gocyclo on a fixture corpus with the discount off. The error-guard discount is typed through `go/packages` and keyed on what the code does, not on the name `err`. The body spans of discounted guards are exposed for coverage, and `TableShape` implements the three conditions of §6.8.
  - CRAP (G1): `crap.Score` maps profile blocks to function spans, closures included, with guard-neutral `cov(f)`; `CRAP = comp² × (1 − cov)³ + comp` in `float64`, compared with the cap unrounded. Function identity (§6.7) is defined once, in `internal/crap`. The build is defined once, in `internal/gobuild` (GOOS, GOARCH, tags, cgo, with the race tag `go test -race` adds). A function in a file the run's build does not compile is not measured, is counted in `crapDetails.not_measured`, and is held to its complexity. The CRAP layer is gate 4, tier 1.
  - Exemptions (G2): `path` globs and `symbol` matched through the scorer's identity; an exempt function is scored and listed under `crapDetails.exempt`, not judged. An entry that matches nothing fails, a `shape: table-switch` entry holds only while the function stays a table, an expired entry exempts nothing, and every exemption in force is printed with its expiry on every run. `exempt.Count` is the live count for the ledger.
  - `baseline` (G3): the only writer of `.go-tops/baseline.json`.
    - `--init` runs the feeding layers (tests, coverage, CRAP, hygiene) and judges none; it writes the measured ledger when the tests are green and every output is non-empty, and refuses when a ledger exists in the tree or at `HEAD`, under `advisory`, or when a feeding layer did not run. A package under its coverage floor does not stop it.
    - The ledger kinds are `functions`, `packages`, `findings`, `suppressions` (`nolint` and `ack`, counted from source comments and `acks.yaml`), `exemptions` and `judged_laws`. The file has sorted keys and one entry per line, and records its build.
    - A plain write only lowers values and removes paid or exempt entries. `--accept-regression --reason --owner` raises or adds an entry, or lowers `judged_laws`, and records it under `regressions`. `--rename OLD NEW` rewrites one function or package key and never a value, and refuses unless the old key has vanished from every `.go` file and the new one exists.
    - Every write needs a ledger that matches `HEAD` and the ledger leg's build, and runs the feeding layers under `enforce: hard`, so it never runs the ratchet judgment.
  - The ratchet (G4): `gate` under `enforce: ratchet` reads the ledger at the merge base of `--base` through git (at the path the base commit's own `go-tops.yaml` names) and judges each kind: a function over the cap against its entry plus 0.01, a package by the two-condition rule, counts per file, the exemption count, `judged_laws`. A raised or added entry without a `regressions` record fails; with no base copy the file is a first ledger and must equal what the run measures. Only the ledger leg judges. Any other leg reports the ratchet as `skip`, naming both builds, and holds to `hard` what the ledger build does not compile. A partial run leaves the ratchet out and ends `partial`. The report gains a top-level `ratchet` object.
  - Calibration (G5): the scorer run over five public Hedronite repos at pinned SHAs against the earlier probe, every difference explained; the caps stand. A gaze cross-check on a fixture module, and `testdata/weak-test`, a module whose untested complex function the gate fails on `crap`.
  - Adoption (G6): `init` writes `gates.crap` enabled at the class cap and keeps `mutation` off with a reason and an expiry, and prints `gotops baseline --init` as the next step. The drop-in workflow stays one job and gains a `workflow_dispatch` trigger (`init` or `refresh`) that runs the baseline on the ubuntu ledger leg. Until M5 its gate step judges exit 1 by ruling C9: every tier 0 to 1 layer passes and the only failed items are the class's required laws, not evaluated. An end-to-end test (build tag `adoption`) takes a legacy module through `init`, `baseline --init`, `check` and the gate under `ratchet`, for a module at the root and in a subdirectory.
  - Self-host and exit (G7):
    - `go-tops.yaml` has CRAP on at cap 10. Every kit function meets the cap except `gate.Execute` and `gate.assemble`, which take `crap` exemptions (owner `maintainer`, expiry 2027-03-31, the M5 date).
    - Thirteen functions were reduced by a split with its own responsibility, or given the tests their coverage lacked: `tests.Parse`, `tests.judge`, `Coverage.Run`, `gate.Main`, `toGateConfig`, `lock.validate`, `cover.Profile.Summarize`, `updateLock`, `checker.tighten`, `gate.makePlan`, `gate.runLayers`, `hygiene` `run.lint` and `parseVulns`.
    - Fixed an M1 hygiene defect: the one lint pass ran with golangci-lint's default caps (3 findings with the same text, 50 per linter), and which files kept their findings varied from run to run, so `baseline --init` and the gate counted different per-file findings on the same code and a first ledger failed the ratchet. The pass now runs uncapped (`--max-issues-per-linter=0 --max-same-issues=0`). Found by the exit demonstration on a scratch clone of vigil.
    - The ratchet's hygiene reason now names each check by its command (`golangci-lint fmt --diff: …`), as the layer does, where it named it by its details key (`format: …`) before.
    - The ratchet calls `hygiene.Fold` for the layer's own folding and `baseline.Feeds.Packages` and `Findings` for the figures of a partial range, so each has one implementation. `baseline` finds a committed ledger from the module directory, so a module in a subdirectory is handled. Fixtures read the protocol version from `Protocol()`.
    - The kit's CI assertion step requires hygiene, tests, coverage and CRAP to be `pass`, and a weekly `adoption` job (also `workflow_dispatch`) runs the adoption end-to-end test.
  - **Repos initialised before M2:** the `go-tops.yaml` that M1 `init` wrote has `gates.crap` with `enabled: false` and an expiry of 2027-01-31, after which `check` fails. Re-run `gotops init --class <class> --force` (it rewrites `go-tops.yaml`, so keep any edits you made aside), or turn CRAP on by hand by deleting the `enabled`, `reason` and `expires` lines of `gates.crap`. Then run `gotops baseline --init` and commit the ledger with the configuration.

### Package (M1)

- **The `gotops` CLI** (the root module `github.com/Hedronite/go-tops`: `cmd/gotops/`, `internal/`, `tools/`). Compiled from the step READYs; protocol 0.4.1, 0.4.2 and 0.4.3 are under Changed. The package is unreleased (0.0.0).
  - Scaffold (G0): the root module at `go 1.26`, with `embed.go` serving the schemas, profiles and AGENTS template; the `gotops` shell with a self-registering command registry, `version`, an unknown command exiting 2 and `--help` listing the commands; the kit's strict `.golangci.yml`; and `ci.yml` with Linux, macOS and language-floor legs, SHA-pinned actions and an aggregate `ci` job.
  - `check` (G2):
    - It validates `go-tops.yaml` against the embedded schema, and `go-tops.lock` and the ledger files against theirs. Each issue is a JSON-pointer line, and an invalid configuration exits 2.
    - It enforces the semantic rules of §12.1: the class column bounds, dated reasons on disabled gates, required laws against the catalog, the advisory expiry, a valid and clean ratchet baseline, a present lock and no duplicate binary names. A config may tighten its class profile and never loosen it.
    - The runtime dependencies are `santhosh-tekuri/jsonschema/v6` and `go.yaml.in/yaml/v3`, with a fuzz target over load and validate.
  - `gate` runner (G3):
    - It runs every enabled layer in range in §3.1 order, judges the laws last, writes `.go-tops/report.json` and exits by the §12.2 table. It takes `--max-tier`, `--fail-fast`, `--only`, `--dry-run`, `--base` and `--json`, and refuses `--dry-run` and `partial` ranges with exit 4 under `CI=true`.
    - Under `enforce: advisory` a started run exits 0, the report keeps the honest outcome with `enforced: false` and `advisory_expires`, and the text says `NOT ENFORCED`.

The tool resolver runs module tools through `go tool -modfile`, downloaded binaries from `.go-tops/bin/<name>` then `PATH`, and reports `tool-missing` when a tool is absent.
  - Hygiene gate (G4):
    - It runs `go mod tidy -diff`, `go mod verify`, the toolchain pin, `golangci-lint fmt --diff`, one adopter-style lint run saved to `.go-tops/lint-style.json`, `govulncheck -json` judged from its findings (time-dependent, database timestamp recorded) and `go-licenses check`. With `deps.depguard: true` the lint config must enable depguard.
    - `internal/lock` loads `go-tops.lock` against the lock schema and checks a downloaded binary's SHA-256 before it runs (exit 2 on a mismatch). `tools/go.mod` pins gotestsum v1.13.0, govulncheck v1.9.0 and go-licenses v2.0.1.
  - Tests and coverage gates (G5, G5e):
    - One `go test -json -race -shuffle=on -count=1 -coverprofile -coverpkg=./...` run, parsed natively. It fails on a failing test, a data race, a build failure, an unshuffled run or no test run, and records packages, tests, skips and the shuffle seed. It needs a C compiler (exit 3 without).
    - Coverage is statements per package and in total from that run's profile. It fails below the class floor and on a missing, empty or block-less profile, merges duplicate blocks and excludes generated files. `internal/cover` reads the profile. The unit-plus-integration merge recipe (`-test.gocoverdir`, `covdata merge`, `textfmt`) is verified.
    - The run overrides an inherited `GOFLAGS`, so `-skip`, `-short`, `-vet=off` and `-run` cannot hide tests. A race is read from the result (a failed test, or exit 66), not from a logged line. The zero-test rule and the `tests` figure count leaf tests only. The coverage gate fails when `gates.coverage.integration.enabled` is true, until the integration merge is implemented.
  - `init` (G6): `gotops init --class <c>` for `binary-cli`, `binary-service` and `library-core` writes the §12.1 drop-in set, with the lock from embedded pins, an `AGENTS.md` block between markers and `GO-TOPS.md`. It never writes a baseline and never overwrites without `--force`.
  - `report`, `lock`, `doctor`, `version` (G7):
    - `report [--format text|json]` renders the last report, and `junit` and `sarif` exit 2 naming M7. There is one text renderer, which the gate prints.

    - `doctor` checks Go against the floor and the pin, a C compiler (exit 3 without one), tools, `GOFLAGS`, `GOTOOLCHAIN` and cgo; `version` lists the pinned tools.
    - `init` enables depguard in the lint config when `deps.depguard` is true, its floor leg guards its toolchain, and `tools/go.mod` is tidied with `go -C tools mod tidy`.
  - Drop-in workflow (G7e): the workflow `gotops init` writes installs the pinned, SHA-checked golangci-lint before the gate on each gate leg, and uploads `.go-tops/` with hidden files included and `.go-tops/bin/` excluded; `init --offline` notes the setup-go cache requirement.

### Changed

- **Protocol 0.4.5** (`GO_TOPS.md`, `schema/`, `profiles/`, `config/`). Mutation, measured before it is built (M4): the text, the schemas and the version for what the engine probe and the design review found. The code that follows it is not in this change.
  - The engine (§6.4, §4.1, §9, §16 item 38): `gotops` gives gremlins every setting as a flag with an empty `--config` file and no `GREMLINS_*` variable, and never obeys a `.gremlins.yaml` or an engine config file elsewhere. Six mutators are on and five off, with each replacement listed. `gates.mutation.engine` accepts `gremlins` alone, so any other value now fails `check`. A package whose name differs from its directory runs the whole module's tests, and a test that fails on the engine's unmutated copy fails the layer.
  - The diff (§6.4, §9): from the diff base to the working tree, untracked files included; module-relative; without the files of other modules. It alone decides which mutants count, and the engine's own `--diff` is not trusted. The base is `--base`, then `gates.mutation.base`, then `origin/main`.
  - Statuses and counts (§6.4): `SKIPPED` is dropped outside the diff and fails on a changed line; `RUNNABLE` fails; `NOT COVERED` means no test in the same package reaches the line; mutants in files the build does not compile are counted in `not_measured`; no engine output with exit 0 is `0 mutants` only when the engine prints `No results to report.`; an interrupted run prints `Shutting down gracefully...` instead and is `fail`.
  - Survivors (§6.4, §12.1, §12.3): the key has one text form, `<file>:<function>:<mutator>:<line_hash>`; one entry explains every mutant with its key; an expired entry fails `check` at tier 0 with mutation on or off; `survivors list`, `explain` and `expire` are defined with their exit codes and write the file in one form.
  - Report (`schema/gate-report.schema.json`, §12.3): the mutation details gain `base`, `base_sha`, `not_measured` and `survivors`, one row per surviving mutant; `timed_out_keys` and `exempt` hold survivor keys. A report with mutation details of the 0.4.4 shape no longer validates.
  - CI floor and the rest (§2, §6.7, §11, §12.1, §17): the first-ledger text matches the drop-in (`--status` takes no base, and the macOS leg runs no gate while a ledger is due); the leg artifacts hold no ledger; the tier 2 `survivors` ledger kind arrives with M6.

- **Protocol 0.4.4** (`GO_TOPS.md`, `schema/`, `profiles/`, `config/`, `scripts/docs/`). The first adoption of a real repository (M3, rulings R5 and R6 and friction rows F2, F3, F4, F5, F6 and F7) bundled into one bump. Text only: no new key and no new schema shape.
  - The kit lint pass (R5, F4; §4.1, §6.7 text, §8.1, §9, §11, §12.1, §16 item 37): gate 1 runs golangci-lint with the kit's `.go-tops/golangci.yml`, named by `gates.hygiene.golangci_lint.config` and written by `init` with `run.relative-path-mode: gomod`.
